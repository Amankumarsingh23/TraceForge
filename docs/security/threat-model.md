# Session 14 threat model

Protected assets are raw and canonical spans/logs/metrics, evaluation datasets and results, comparisons/gates, SLO definitions/evaluations, incidents/events, credentials, and finite shared compute. The modeled attacker holds one tenant's scoped credential, controls OTLP fields and agent questions, and may cause retrieved text or tool output to contain instructions. They do not possess the operator's PostgreSQL/ClickHouse password, filesystem, Docker socket, or private network access. Compromise of that trusted host defeats this local boundary.

The TLS gateway authenticates an opaque key against PostgreSQL on every request, checks its scope, resolves the trusted tenant, and selects a fixed private backend. Payload attributes, query parameters and browser headers never select a backend. A mismatching `X-Tenant-ID` or recognized OTLP tenant claim is rejected. Three fixed namespaces keep admission state bounded. Authorization occurs before proxying/ingestion. Private backend health and diagnostics are not public tenant endpoints; only a manage key can read its own diagnostics through the gateway.

Credentials use 32 cryptographically random bytes; PostgreSQL stores a SHA-256 verifier and revocation state, never the plaintext key. High-entropy tokens make a slow password KDF unnecessary here. Separate read/ingest/manage credentials avoid granting writes to browser users. Bootstrap emits local private files once and now refuses to overwrite an existing output. Revoke an explicit credential ID with `traceforge-secure --mode revoke --tenant alpha --credential-id ID` using trusted operator database configuration. Revocation affects subsequent requests; it does not cancel already admitted work. There is no offline auth cache. Database authorization failure closes new requests with unavailable, rather than accepting stale authority. Local fixture keys have no automatic expiry; key rotation and certificate renewal are operator work, not a production identity service.

TLS uses a generated seven-day self-signed development CA/certificate, verified by the clients. Both exposed Collector hops and the gateway use TLS. Internal fixed backend connections use the trusted Docker network; database connections remain password-protected local development connections. Secure Compose removes the unauthenticated backend/Collector host mappings. The base Compose file deliberately remains **Legacy compatibility mode** and must not be deployed as a tenant boundary. Direct database ports are loopback-only trusted operator surfaces, not tenant APIs.

The Next server encrypts the read credential into a 15-minute AES-GCM authenticated, HttpOnly, SameSite=Strict cookie. Its independent server secret is private. Login/logout require the same Origin, the login body is bounded, and upstream identity must have exactly read scope. Browser JavaScript does not receive a credential in application data or localStorage. Proxy requests use a fixed upstream and authenticated cookie; upstream cache headers are no-store. For HTTPS deployment set `TRACEFORGE_COOKIE_SECURE=1`. The local HTTP browser demo cannot offer a Secure-cookie transport guarantee. Cookie validation alone is not revocation: every actual protected backend fetch checks the credential online. Secure browser execution was blocked by automatic approval review in this session; unit/build checks do not replace that verification.

## Resource and privacy limits

Gateway limits: 1MiB OTLP messages, eight HTTP/2 concurrent streams, 16 gRPC connections, 24 HTTP connections, two read and two ingest operations per tenant, six global admitted operations, token rate eight/second and burst twelve per tenant; six-second export deadlines and bounded HTTP deadlines. Auth has a four-connection PostgreSQL pool, statement/context timeouts, and no unbounded credential cache. Separate backend processes isolate metric-cardinality state, normalization and batching; each retains existing signal/query/row/byte/window/cardinality limits. Collector memory limiters, 16-entry queues, one exporter consumer and ten-second retry budgets constrain volatile buffering. Agent input is at most 8KiB HTTP/1,000 question characters, four global/two per-tenant executions, bounded context/tool JSON/output, model/tool/step/attempt counters and a 20-second overall deadline. Management input is at most 16KiB. Security results return at most ten records with a 256KiB per-record budget. These are local guardrails, not capacity guarantees or strong scheduling fairness across shared CPUs, disk and database pools.

Span/log normalization now covers known credential/PII patterns in values, common sensitive keys, prompt/completion bodies, scope/schema/event/status fields and nested content. Metric metadata with sensitive keys/values is rejected rather than merged by redaction into a shared identity. Source-side AgentOps still emits IDs, counts and classifications instead of raw questions/context/tool arguments/answers. React renders stored text without HTML execution. Pattern-based redaction is incomplete: arbitrary encodings, unfamiliar secrets, semantic personal information and free-form content may evade it. Raw adversarial fixtures contain synthetic instructions only; reports store classifications and trace IDs, not their raw text. No universal DLP claim is made.

Read-only agent tool calls require all of: an allowed name, valid bounded arguments, application-side resource ownership, and an allowed operation before execution. Retrieved documents are an explicitly untrusted user-context block; tool output stays in its tool role. These placement instructions help but are not the authorization boundary. The tested synthetic disclosure marker guard is deliberately narrow. No shell, network-fetch, filesystem-write, customer-data or destructive tool was added.

## Residual risks and review

No OIDC/SSO, per-tenant database role/RLS, production secret manager, distributed quotas, durable security worker, container vulnerability certification, independent penetration test, live-provider attack test, or production capacity claim. All tenant backends share an operator database principal and infrastructure; fixed backend configuration and the private network are trusted. A future tenant-scoped response cache must key by verified tenant as well as query and authorization policy; today responses are not cached. Dependency audit findings and unavailable checks are recorded in the session journal. Session 15 integration remains separate work.
