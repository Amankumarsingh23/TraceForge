# Paired comparison contract — Session 9

`evaluation.comparison` is pure: it reads frozen run snapshots and never calls a provider, edits scores or queries telemetry. Cases are joined by stable ID, not array position. Duplicate/missing/unexpected cases, incomplete runs, dataset/corpus/label/evaluator/mode differences invalidate the comparison. Intended prompt/model/retriever/context changes are recorded rather than rejected. Metric cutoff differences invalidate recall/RR/retention only; pricing incompatibility invalidates cost while quality may remain meaningful. Known Session 8 v1 scoring/HTTP measurement definitions have an explicit legacy mapping; legacy snapshots are labeled and never assigned invented manifests or pricing versions.

Manifests contain canonical allowlisted config snapshots, stable config ID, content-derived version and SHA-256 hash. They freeze dataset/corpus/prompt/source identities, retriever parameters, requested model/provider/mode, retrieval K separately from evaluation K, context limit, generation/tool settings, evaluator/scoring definitions, pricing/currency and runtime/HTTP timing scope. No environment or credentials are copied. Nested secret fields/credential-bearing values are rejected. Run snapshots are checked against their manifests. PostgreSQL references manifest checksums; config/policy/comparison/decision history rejects updates/deletes. A new policy version creates a separate decision, while repeating identical comparison/policy writes is idempotent.

The paired mean delta uses only IDs scored on both sides. Own-cohort full-run means, eligibility/scored/N/A/missing/error counts and coverage remain visible, so survivor bias is inspectable. Failed execution contributes zero to execution success, never a made-up quality score. Correctness transitions are both-correct, both-incorrect, improved, regressed or missing/ineligible; execution transitions and new critical unsupported/contradictory claims are separate. Actual case/trace links retain pending availability.

Absolute change is candidate minus baseline. Fraction metrics also show percentage-point change = delta×100, distinct from relative change = delta/baseline. Zero baseline makes relative change undefined. Quality is higher-is-better; latency and money are lower-is-better. Positive change is therefore not universally good.

Quantiles use linear R7 interpolation at `(n-1)*p`; mean, p50, p95 and p99 include sample counts. Successful and failed HTTP wall times are reported separately, plus all attempts. Paired latency gates compare the same successful case cohort, not different survivors. Below 100 observations, tail estimates carry a small-sample warning. Fixture latency is local/offline HTTP workload evidence, not model inference speed or production capacity.

Quality mean-difference bootstrap samples **paired differences**, after sorting stable case IDs, with seed9 and 1000 resamples. The diagnostic interval is the 2.5/97.5 percentile using R7. Fewer than five pairs is insufficient; identical differences yield a labeled degenerate interval. Correlated/paraphrased synthetic questions, small sample and author-only labels prevent production significance claims. Intervals are not mandatory gates.

Money uses canonical Session 7 attempt summaries already captured by the runner. Nano-USD totals remain integers; mean/relative money arithmetic uses Decimal (28 significant digits for repeating means/ratios). Known partial subtotals are distinct from full totals. Any incomplete cost coverage or incompatible price hash/version/currency leaves full comparison unknown; absent usage is never zero actual usage. Known input/output subtotals and complete-usage case counts remain visible. Fixture rates and counters stay synthetic/hypothetical. Telemetry replay is not a model call and does not change canonical accounting.

Run `scripts/session09-experiments.ps1` with the local fixture app and healthy stack. It executes five real 35-case runs: baseline/repeat K3-context2, K3-context1, K1-context2 and explicit missing-usage fixture, all scored at K3. Controlled gate tests are saved separately in `gate-fixtures.json`, never persisted as measured runs or linked to invented traces. The comparison CLI can reuse completed runs: from the Python directory, `python -m evaluation.compare_cli BASELINE_ID CANDIDATE_ID --policy evaluation/policies/offline-v1.json --report ../../artifacts/session09/manual.json`, with server-side PostgreSQL credentials. There is no deployment action.
