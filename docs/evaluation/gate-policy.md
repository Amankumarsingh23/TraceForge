# Versioned gate policies — gate-v1

Policies have stable ID/version/hash, bounded unique rule IDs, explicit mandatory/advisory status, units and thresholds. Unknown metrics/operators/fields, inconsistent units, invalid/negative/nonfinite ranges, invalid critical IDs, unsupported combinations and empty mandatory sets are rejected. Supported checks: minimum/maximum metric value, maximum absolute degradation, maximum relative quality degradation or lower-is-better increase, minimum coverage/matched count, maximum execution failure rate, critical protection and required mode/semantic review. Relative thresholds are bounded ratios0–1. Fractions use0–1, latency ms, cost nano-USD, matched sample counts integers.

Every rule returns PASS/FAIL/INCONCLUSIVE, or N/A when a policy explicitly permits a truly inapplicable metric. Incompatible evidence never gets a numeric comparison. Missing metric/undefined relative baseline/missing cost is INCONCLUSIVE. Insufficient coverage/matched samples are evidence insufficiency and INCONCLUSIVE, not permission to ignore missing cases. Known quality/cost/failure-rate violations are FAIL. Mandatory critical regressions/new failures/new unsupported or contradictory claims FAIL; missing protected evidence is INCONCLUSIVE. Protected IDs are independently designated from all existing multi-document/truncation cases before candidate execution, with a recorded rationale.

Overall precedence: globally invalid comparison → INCONCLUSIVE; otherwise confirmed mandatory violation → FAIL; otherwise missing mandatory evidence → INCONCLUSIVE; otherwise all required checks satisfied (or explicitly allowed N/A) → PASS. Individual checks remain visible even when another check determines the outcome. Only PASS satisfies that exact policy scope. Nothing is automatically deployed/promoted.

`support-offline/v1` is a teaching policy: fixture mode, correctness≥0.90, correctness absolute degradation≤0.01, full correctness coverage,35 matched cases, zero execution failures and zero protected regressions. Thresholds are declared learning defaults, not an independently validated production release policy. `v2-strict` raises the correctness floor to0.99, retaining a separate decision for the same actual comparison. The cost-evidence diagnostic requires complete comparable estimated cost; missing-usage runs remain INCONCLUSIVE.

`production-evidence/v1` requires live mode, independently verified semantic review, complete correctness coverage and bounded estimated cost increase. Current fixture runs are INCONCLUSIVE under this profile; fixture PASS is never production approval. No live provider, paid judge or independent human calibration was executed. Human review cannot be inferred from deterministic exact-rubric scores.

Read-only endpoints: `/api/v1/experiments`, `/api/v1/comparisons`, `/{comparison_id}`, `/{comparison_id}/cases` under comparisons, and `/api/v1/gates/{decision_id}`. Lists accept limit1–50/after; experiment cursors are64-character hashes, comparison cursors32-character IDs, case cursors bounded case IDs. Existing query slots/deadlines/SQL timeouts/cancellation/4MiB response limits apply. Browser proxies accept fixed same-origin paths only. Comparison UI filters server-produced transitions and links both actual cases/traces; it does not implement separate scoring semantics.
