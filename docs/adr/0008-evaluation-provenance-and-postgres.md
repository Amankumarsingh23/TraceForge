# ADR 0008 — Transactional evaluation metadata and constrained evidence scoring

Accepted, Session 8, 2026-11-13.

Use PostgreSQL for dataset versions/cases, frozen evaluation runs and unique per-run case results. Keep ClickHouse as the canonical execution-telemetry store. Python writes metadata through pinned Psycopg 3.3.9; Go serves bounded read-only APIs through pgx/v5 5.13.0. Primary compatibility references: [Psycopg installation](https://www.psycopg.org/psycopg3/docs/basic/install.html), [transaction contexts](https://www.psycopg.org/psycopg3/docs/basic/transactions.html), [pgxpool](https://pkg.go.dev/github.com/jackc/pgx/v5/pgxpool). Python 3.13 and Go 1.27 meet reviewed package requirements; existing dependencies were preserved.

Migration 0001 creates dataset/version/checksum identities, cases, runs, JSONB metrics/judgments, foreign keys, status/count checks and unique `(run_id,case_id)`. An advisory transaction lock serializes migration; version bookkeeping is explicit. Store methods transactionally register/check immutable dataset content, create a new run ID, insert each case exactly once and increment counts. Completed runs cannot accept more results through this boundary. Failed insert transactions roll back counts. Re-running creates a new identity, never overwrites a completed evaluation. Interrupted-run aggregates cover persisted results, not unsaved in-memory executions. A process killed before finalization may leave `running`; no durable worker/resume service is claimed.

Run metadata freezes corpus/dataset hashes, prompt/retriever/evaluator versions, provider/requested model, fixture/live mode, selected cases, K/context cap, call/attempt/tool bounds, source checksum and actual Git HEAD/dirty state. Results retain actual application run/trace identity, returned model, retrieved/supplied IDs/content hashes, evaluated/original output, failures, applicability/coverage, measured HTTP latency and available canonical usage/cost. Original evidence is synthetic and deliberately persisted in metadata, never added to generic span/log content. No telemetry rows are copied to PostgreSQL.

Generate constrained fixture claims from actual question/context using application extraction rules, independently of evaluation labels. Render displayed answer from those claims and validate correspondence before scoring. Score exact approved values and independent document evidence mappings; require actually supplied support for groundedness and citation correctness. Keep correctness, required facts, groundedness, citation validity/availability/support/coverage and abstention distinct. Arbitrary free-form output receives pending semantic review, not word-overlap entailment scores. Human review is separately documented/pending; no judge or calibration claim.

The runner defaults to fixture execution, bounded sequential requests and one model attempt/call, no executable tools. Live requires both explicit live and billable flags and existing authorized server credentials; no paid calls were made. It sends no labels/reference answers to the application. Evaluation IDs are bounded traceforge metadata. Trace lookup is asynchronous/bounded and never required for result persistence. Explicit diagnostic output transforms preserve provenance and original outputs.

Go uses parameterized queries, four query slots/pool connections, 2s request deadline, 1.8s SQL statement timeout, at most 50 items, keyset cursors and 4MiB response cap. PostgreSQL failure affects evaluation queries while existing trace/log readiness remains independent. The scratch container needs explicit PostgreSQL user/database in parser configuration; OS-user discovery fails for its non-root UID. This local Compose/loopback deployment uses internal plaintext PostgreSQL and process-side credentials; production TLS/auth/RBAC/tenant enforcement remain out of scope. Query connections default to read-only, verified by an actual rejected UPDATE. No browser DB access or credentials.

Next adds fixed same-origin evaluation GET routes and focused run/case views, with shared cancellation/deadlines/body caps. It displays numerators/denominators, coverage/N/A/pending/errors, synthetic provenance, source facts, output transforms, claims/citations and actual trace navigation. It does not compare runs for promotion or implement deployment gates. Initial relevance labels are author-reviewed synthetic evidence, not independent human calibration. Metrics/edge policies and review workflow are in `docs/evaluation/`.
