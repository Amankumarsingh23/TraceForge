# ADR 0006 — Independent log rows, bounded persistence and exact correlation

Date: implemented 2026-11-12–13 (Asia/Calcutta). Status: accepted for Session 6.

## Signal boundaries and application instrumentation

Keep one Collector and Go OTLP/gRPC listener. Register the generated LogsService alongside TraceService. Logs use a separate normalization package, fixed-worker queue, capacity/accounting registry and `traceforge.logs` MergeTree table. The trace schema, receiver/acknowledgment algorithm and reconstruction remain intact. Shared database connections, CPU, gRPC transport limits and host resources remain shared; independent budgets do not imply infrastructure isolation or production fairness guarantees.

The Go demo uses standard `log/slog` through `otelslog` 0.21.0, OTel log SDK 1.47.0 and OTLP/gRPC log exporter 0.23.0. Exact module proxy requirements match the already-pinned OTel 1.47.0 stack; no blanket upgrade. Consulted the official [bridge](https://pkg.go.dev/go.opentelemetry.io/contrib/bridges/otelslog), [log SDK](https://pkg.go.dev/go.opentelemetry.io/otel/sdk/log@v1.47.0), [log data model](https://opentelemetry.io/docs/specs/otel/logs/data-model/) and [OTLP delivery spec](https://opentelemetry.io/docs/specs/otlp/), plus installed generated schema/SDK implementation.

Tracing and logging share the same service/version/environment resource factory. LoggerProvider, bridge logger and shutdown ownership are explicit rather than global. SDK log batching is capped at 512 records, 128 per export, 1s interval and 3s export timeout; exporter timeout is also 3s. Startup is a legitimate standalone log. `InfoContext`, `WarnContext` and `ErrorContext` use the active gateway, validation or `payment.process` context. Context-aware method names alone do not export logs without the bridge/provider/exporter. Provider shutdown has a five-second bound after HTTP draining; initialization and asynchronous SDK export failures are not treated as persistence proof.

## Normalization, timestamps and privacy

Traverse every ResourceLogs/ScopeLogs/LogRecord. Reject malformed group envelopes and excessive request counts; individual malformed records contribute exact partial-success counts. IDs may both be absent, or trace-only. Present trace IDs must be 16 nonzero bytes and span IDs 8 nonzero bytes; this implementation rejects span-only records because span identity is scoped to a trace. No identifiers are fabricated and no existing trace/span is required.

Preserve source and observed timestamps as nullable DateTime64(9), flags, numerical/original severity, event name, typed body/attributes, resource/scope metadata, schema URLs, dropped counts and the sanitized full known LogRecord in protobuf JSON. Severity 0–24 is accepted; 18 is in ERROR, not an invalid level. Effective time prefers source, then observed, then a receiver-ingestion timestamp explicitly labeled `time_source=ingestion`. Missing source/observed fields stay null. Ingestion time is receiver normalization time, not a recovered event time or a measured database commit timestamp. The API emits RFC3339Nano strings. Frontend relative arithmetic uses the existing BigInt parser.

Protobuf JSON retains AnyValue type tags, decimal int64 strings and base64 bytes. `body_text` is the plain sanitized string for string bodies, otherwise the typed JSON representation; missing body is JSON null/empty text. Unknown protobuf wire fields are not exposed by protobuf JSON. There is no attempt to infer arbitrary external event IDs: string `log.record.uid` is copied to `source_event_id`, and all validated attributes remain independently available. EventName is an event category, not a unique instance identity.

Reuse the trace normalizer's key-based typed-value sanitizers on clones. Apply them to log/resource/scope attributes and nested body maps/arrays. Add a log-specific free-form string rule that replaces the whole string when recognized embedded Bearer/Basic, password/passwd/api-key/token/secret assignments or a private-key header is detected. Reuse URL credential/sensitive-query sanitization. Sanitize body text, duplicated JSON representations and supported free-form metadata before insertion; do not log raw input/driver errors. Binary values under nonsensitive keys remain opaque, not comprehensively scanned. Key/pattern rules can over-redact and miss arbitrary confidential content; this is not DLP, production privacy certification or permission to send real secrets.

Limits: 4MiB gRPC message, 1000 resource groups/scopes/records, 64KiB record, 16KiB resource/scope, 4KiB typed strings/bytes, 256 nested items and bounded depth. An iterative preflight checks recursive shape before protobuf sizing/cloning; wide child lists are rejected before growing the work stack. Known-valid trees also receive an exact whole-protobuf size check. Malformed deep records are rejected individually without recursively cloning them. The gRPC cap remains the outer transport boundary.

## Storage identity and queries

Migration 0002 is repeatable and leaves spans unchanged. Logs have a random 128-bit lowercase hex storage-row identity, separate optional source-event identity, optional context IDs and the fields above. `ORDER BY (effective_time, log_id)` and monthly effective-time partitions support bounded recent-time scans. Service/severity/body/trace filters may scan within the time window; trace correlation has no trace-ID-first index today. No full-text infrastructure, projection or schema overhaul is introduced.

No deduplication by trace ID, span ID, message, timestamp or source UID. Three identical records are three events, and replay adds new rows/IDs. MergeTree has no event-uniqueness constraint. Generated row identity stabilizes pagination of a stored observation; it does not establish exactly-once source delivery. A foreign key to observed spans would incorrectly discard startup, unsampled, late/out-of-order or independently collected logs.

`GET /api/v1/logs` defaults to the last hour. `GET /api/v1/traces/{trace_id}/logs` defaults to the last 24 hours and does not first load a trace. Both accept UTC `from`/`to` (maximum 24h), service, `min_severity` 0–24, trace ID, optional span ID (requires trace ID), literal case-sensitive `text` up to 256 UTF-8 bytes, page size 1–100 and an opaque cursor. Correlation binds both IDs; timestamps/services never establish a join. Trace-only records remain visible at trace scope.

Parameterized reads use the existing ClickHouse execution/read/memory caps, a two-second API deadline, two active log queries, a bounded physical-row page/sentinel and 4MiB stored-content/8MiB encoded response caps. Ordering is `effective_time DESC, log_id DESC`; versioned cursors store exact nanosecond position, absolute bounds and every filter. Decode rejects unknown/trailing fields, invalid positions, wrong offsets and changed filters. Pagination is non-snapshot: late records can appear ahead of the cursor; reset/refresh to find them. No custom query language, regex search or HTTP SQL is exposed. Structured sanitized 400/413/503/504/internal errors preserve meaning.

## Persistence and Collector policy

Adapt the proven Session 4 queue lifecycle rather than generically refactoring the working trace pipeline. The log-specific bounded engine and its deterministic tests retain ticket ownership, whole-request batching, shared lifecycle writes, late-cancellation ambiguity and final-drain behavior. This deliberately duplicates a small algorithm so trace behavior and budgets remain independent; future fixes to common lifecycle logic need review in both packages.

Log defaults: 32 queued/normalizing positions, 16 handlers, 64 owned jobs, 8192 reserved records, 64MiB conservative payload units, one writer, 256-record target/50ms assembly wait, 50ms combined admission wait, 3s write/5s export deadlines. Reservations charge repeated resource/scope data per record before normalization and are checked against retained data. These units are not exact heap/RSS. Fixed labels and a bounded diagnostic sample ring expose state via `/metrics/logs` and `/debug/log-ingestion`; no user OTLP metrics ingestion.

The valid subset must complete synchronous ClickHouse insertion before an OTLP success or exact partial-success response. Full success leaves `partial_success` unset. Empty requests do not write. Temporary admission/database errors use Unavailable/RetryInfo; unfit hard-budget requests use InvalidArgument. No internal write retries or durable spool. Cancellation before writing can skip a job; cancellation during shared writing does not cancel peers and can still persist the canceled caller's rows.

Collector logs use a distinct exporter instance with 64 queued requests, one consumer, 6s attempt timeout and finite 60s retries (1–5s backoff); no detailed log debug exporter. The trace pipeline/its debug output remain unchanged. SDK/Collector acceptance precedes backend storage, in-memory queues can overflow/crash, retries can expire, and lost acknowledgments/ambiguous writes can duplicate rows. The precise guarantee remains persistence-confirmed backend acknowledgments with possible duplicates or loss under stated failures, not unconditional at-least-once or exactly-once delivery.

Main shutdown drains trace and log engines concurrently under one existing deadline, then closes the shared pool and bounds worker/gRPC/HTTP exit. A log signal cannot consume the trace queue/payload counters, but a truly stuck driver still depends on cancellation/pool closure/process termination. SIGKILL bypasses drain; active-write outcomes may be unknown.

## Thin UI

Extend only approved same-origin Next log routes, reusing the bounded server-side forwarding function. Server proxy code is separate from browser log models/helpers. `/logs` shows actual filters, physical rows, severity, exact times, expandable typed details and associated-trace links. Missing traces show the established 404 page; no matching span is invented. Detail adds all-trace versus selected-span logs with explicit IDs, trace-only labels, last-24h effective-time bounds and refresh for late arrivals. General search retains applied absolute bounds until changed/cleared; refresh repeats that window. Abort/generation guards, honest empty/errors, safe React text and BigInt relative offsets reuse Session 5 behavior. No automatic updates, log-query language, AI diagnosis or future-session feature is added.
