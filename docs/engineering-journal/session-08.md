Implemented and verified 2026-11-13, Asia/Calcutta; starting commit `bdc192f`. Scope stops after Session 8. No paid generation/judge calls, cross-run promotion, deployment gates, training, vector infrastructure, metrics ingestion, production auth or remote push.

## Files and data flow

The Session 7 Python app now optionally accepts `context_limit` 1–3, `output_format=structured` and bounded evaluation run/case IDs. Default text/tool behavior remains available. `agent_demo/constrained.py` extracts closed-domain claim objects from actual supplied document text using application-side rules, then renders their displayed answer. It never imports evaluation labels. `agent.py` records evaluation metadata in real child spans and returns actual supplied-document content hashes. `/ask` rejects hidden expected-label fields.

`evaluation/data/support-eval-v1.json` independently specifies 35 synthetic cases and twelve atomic source facts from the real D01–D12 support corpus: 24 single-topic/paraphrases, five two-document cases, one three-document truncation case and five unanswerable/ambiguous/irrelevant cases. Thirty are retrieval-eligible. Labels include relevance, exact fact alternatives/evidence quotes, citation requirements, answerability/reference rubric and author-review provenance. They were not derived from measured retrieval output. Independent human review/calibration remains pending; author review is not a claim of independent human annotation.

`evaluation/dataset.py` validates corpus/version/hash, case identity, document references and fact evidence. `metrics.py` computes actual retrieval/context metrics and macro means with applicability/coverage. `scoring.py` validates rendered-claim correspondence and uses independent exact source values/evidence mappings, not token overlap. Free-form semantics remain pending. `runner.py` executes the actual HTTP application with frozen settings, captures actual output/IDs/hashes/failures/trace links, scores independently, performs bounded asynchronous visibility/usage lookups, then writes transactional metadata. Explicit controlled transforms preserve original and evaluated outputs. `experiments.py` runs diagnostics; these are not deployment comparisons.

PostgreSQL migration 0001 creates version/checksum datasets, cases, frozen runs and unique case results with JSONB metrics/judgments, foreign keys and count/status constraints. Psycopg 3.3.9 writes bounded transactions. No ClickHouse telemetry is duplicated there. Dataset-version changes are rejected on checksum mismatch, duplicate case insertion rolls back counts, completed runs reject more results, and reruns have distinct identities. Go `internal/evaluations` uses pgx/v5 5.13.0 for bounded parameterized reads/read-only sessions. Compose passes server-side PostgreSQL credentials; `.env` was preserved. New API routes and Next run/case pages expose provenance, metrics/coverage, source facts, actual outputs, diagnostics and trace navigation. Evaluation failure does not block existing trace/log reads.

## Metric definitions and policies

Full formulas are in [metric-definitions](../evaluation/metric-definitions.md); review workflow is in [dataset-and-rubric](../evaluation/dataset-and-rubric.md), design in [ADR 0008](../adr/0008-evaluation-provenance-and-postgres.md). Precision denominator is K even for short rankings. Duplicates consume original positions but cannot inflate unique relevance. Relevant-set metrics are N/A with no relevant labels; successful empty retrieval with relevant labels scores zero. Missing/failed executions remain unscored, with execution failures and scoring coverage visible. Context retention is N/A when no relevant result was retrieved. Macro numerators are sums of per-case scores, denominators are scored-case counts; they are not pooled raw document counts.

Groundedness requires exact approved claim values supported by actually supplied evidence. Correctness separately requires expected facts and appropriate abstention without false/unknown claim values. Missing facts can make an entirely grounded answer incorrect/incomplete. Citation validity, actual availability, exact support and coverage are separate. Removing one citation reduces coverage; it need not invalidate other existing correct citations. Empty/abstaining output receives no automatic perfect semantic scores. Unanswerable abstentions get N/A for inapplicable claim/citation metrics. All semantics are constrained synthetic rubric checks, not general entailment.

- Fault controls use an actual complete support-027 output with both required facts before applying deliberate mutations. Both original and transformed outputs remain inspectable, and the trace describes the original actual execution. These are evaluator diagnostics, not claims that the model naturally generated those mistakes.
- A fixture timeout case has failed execution, null metrics and zero retrieval scoring coverage, with real run/trace identity. An actually unavailable loopback lookup retains its real trace ID and pending visibility while preserving valid evaluation results; no fake trace is generated.
- Repeating frozen K=3/context=2 matches all 35 deterministic case scores, judgments, actual ranking/context IDs, supplied hashes and evaluated outputs, with the same configuration checksum and distinct evaluation/application/trace IDs. Timing is explicitly excluded from identity/equality. Report records actual Git HEAD plus dirty=true and source checksum, rather than pretending uncommitted code was already in HEAD.
- Initial diagnostic selection was incomplete even before mutation; review replaced it with an explicitly verified correct control, so a missing-required-fact test cannot pass solely because the original answer was already incomplete.

## Commands, limits and readiness

Use the root README and `scripts/session08-evaluate.ps1 [-Experiments]`. Direct invocation from `examples/agent-demo` requires process `POSTGRES_PASSWORD`; `.venv/Scripts/python -m evaluation.runner` defaults to fixture, K3/context2, one sequential request, one model call/attempt, zero executable tools. All HTTP/SQL calls are bounded. Metadata/query credentials remain server-side. The run API accepts limit 1–50 plus after cursor, uses four slots/connections, 2s request/1.8s SQL deadlines and 4MiB response cap. The proxy rejects arbitrary destinations/paths. Run/case results are independent of eventual trace visibility. User-level auth/TLS/tenant enforcement is not implemented beyond restricted local deployment.

No independent human annotations, judge agreement analysis or live inference/billing evidence exist. Closed-domain literal extraction and exact rubric checks can validate this synthetic engineering pipeline, not arbitrary natural-language quality. There is no evaluator job queue/resume/recovery service; forced termination may leave a running/partial run, and persisted counts are the confirmed lower bound. Session 9 can build comparisons/gates on the frozen metadata and explicit coverage, but neither is implemented here. Session 3 theory remains separately pending.

2. All D1/D2/D3 are retrieved in the five results, so Recall@5=1. Only D1 survives the first-two context selection, so supplied-context coverage=1/3 (and relevant retention=1/3). Context assembly lost evidence. Raising K does not fix an unchanged context cap/selection rule.
3. The 30-day return and photographs claims are supported by the teaching D1/D2; the 24-hour refund arrival claim is unsupported. Groundedness=2/3 and required-fact coverage=2/2=1, while overall correctness fails because of the unsupported extra claim. An answer may be grounded but incomplete/incorrect relative to the question or rely on false source evidence; a true answer can be ungrounded if no supporting evidence was actually supplied. These teaching facts are not silently inserted into our different real corpus labels.
4. D1 supports the return-window claim; D3 does not support photographs. Citation correctness=1/2 and supported citation coverage=1/2; ID validity/availability alone would be 2/2 if both documents were supplied. Existence is not evidence support. High word overlap can persist after negation ("NOT accepted"), so overlap is not entailment.
5. Report 40 attempted, 35 successful (87.5%), five execution failures. Of successful cases, 30 retrieval-eligible and five N/A. Determine applicability for the failed cases from their independent labels: if all five were eligible, report 35 eligible, 30 scored, five N/A, five failures and coverage 30/35; otherwise use 30 plus the actual eligible-failure count. Never infer failed cases' applicability from missing output or silently turn their missing scores into zeros. Freeze dataset/corpus versions/hashes, case IDs/labels, prompt/retriever/evaluator/rubric/source versions, provider/model/settings, K/context bounds, mode, seed policy, Git/build/dirty identity, pricing provenance and actual case/trace outcomes. Perfect deterministic fixture scores validate only the constrained pipeline under those labels; live output quality needs separate actual outputs and trustworthy independent evaluation.
